# 《亮车计划》可玩原型

> 可玩原型：美术已换成 **AI 生成的位图素材**（本地 ComfyUI · MiniMax H3 · 手绘厚涂风格）。

## 怎么跑

**双击 `play.cmd`**（推荐）。它会自己找 Chrome / Edge 并用它打开，绕开系统的 `.html` 关联。

> ⚠️ 这台机器上 `.html` 默认关联到 **Internet Explorer**，直接双击 `index.html` 会是空白页。

| 文件 | 用途 |
|---|---|
| `standalone.html` | **单文件版**（1.03MB，含全部素材），发给别人测最省事 |
| `index.html` + `assets.js` + `levels.js` + `game.js` | 开发版 |
| `play.cmd` | 不依赖文件关联的启动器 |

改了代码后重新生成单文件版：`node tools/bundle.mjs`

**调试参数**：`?lv=3` 指定关卡 · `?fresh=1` 清存档 · `?debug=1` 暴露 `window.__cw` · `?auto=1` 自动扫射

## 美术素材管线

全部素材由本地 ComfyUI 生成，**零 API 费用**，单张约 40 秒。

```
提示词 → ComfyUI(MiniMax H3) → 绿幕图 → 色相抠像 → WebP → assets.js → 游戏
```

### 关键文件

| 文件 | 作用 |
|---|---|
| [`../docs/art-prompts.md`](../docs/art-prompts.md) | 全部提示词 + 实测参数 + 踩坑记录 |
| `../tools/gen.mjs` | 批量生成（直连 ComfyUI HTTP 接口，顺序跑） |
| `../tools/make-jobs.mjs` | 生成任务清单 `jobs.json` |
| `../tools/keyer.html` | 色相绿幕抠像（Chrome 无头渲染成透明 PNG） |
| `../tools/process-assets.ps1` | 抠像 + 缩放 |
| `../tools/to-webp.mjs` | PNG → WebP（0.82 质量） |
| `../tools/make-assets.mjs` | 打包成 `assets.js`（base64 data URI） |

### 为什么用 WebP

PNG 带 alpha 太重：19 张素材 **8.87 MB**，超过微信主包 4MB 限制。
转 WebP 后 **0.68 MB**，画质几乎无损。

### 素材清单（19 张）

| 类型 | 数量 | 说明 |
|---|---|---|
| 车辆 | 6 | 轿车 / 面包车 / 跑车 / 越野车 / 货车 / 黑轿车 |
| 器物 | 4 | 砖墙 / 陶罐 / 老窗 / 轮毂 |
| 污渍 | 4 | 软泥 / 厚泥 / 硬垢 / 漆损 |
| 特效 | 2 | 泡沫 / 水花 |
| 背景 | 3 | 户外 / 清晨 / 黄昏 |

### 两个实测坑

**1. 模型不听「纯绿 #00FF00」**
实际产出 rgb(85,227,132)。抠像必须按色相判定（`绿比红蓝高多少`），不能按到纯绿的距离。

**2. 会自己加暗角**
提示词写 `no vignette` 也无效。当素材用没影响，当背景用要后期盖掉。

### 重做素材

```bash
node tools/make-jobs.mjs          # 生成任务清单
node tools/gen.mjs                # 批量生成（约 20 分钟）
powershell -File tools/process-assets.ps1   # 抠像 + 缩放
node tools/to-webp.mjs            # 转 WebP
node tools/make-assets.mjs        # 打包 assets.js
node tools/bundle.mjs             # 重出单文件版
```

## v3：给游戏一个"代价"

### 为什么加水量

v2 的问题不是内容少，是**没有失败条件**：

- 进度永远只增不减，看一眼就知道"扫干净就行" → 没有任何决策
- 既然没有挑战，**升级就只是让一件本来就容易的事变得更快** → 满级即无聊
- 关卡 8 秒就能洗完 → 内容被瞬间吃完

所以 v3 加了**水槽**：按住冲洗就在耗水，水用完还没洗完 = 这一单砸了。

现在每一秒都在做权衡：**这块要不要再补一遍？值不值得？**

### 三条升级线（幅度收窄过）

| 升级 | 效果 | 满级 / 1 级 |
|---|---|---|
| 💦 水压 | 笔刷半径 3.8% → 5.2% 屏宽 | 面积 ×1.6 |
| 🔫 喷嘴 | 快划补点 1 → 4 | 减少断点 |
| 🧴 除油剂 | 油渍清除 ×0.55 → ×2.4 | 油渍更好冲 |

价格 `60 / 130 / 240 / 400`，一条线满级 830。

> **v2 的教训**：最早做的是 5 倍效率（1 级洗完一辆车 8 秒，5 级只要 1.6 秒）。
> 升级越强，内容被吃掉得越快 —— 满级那天游戏就结束了。
> 现在压到约 2 倍，并且**关卡水量按"该关预期装备等级"反推**，升级变成"打得过下一关"的钥匙。

### 星级 = 省水

- 3★：洗完且剩水 ≥ 25%
- 2★：洗完且剩水 ≥ 8%
- 1★：洗完
- 0★：水用完了（仍然按进度给金币，可以退回上一单刷钱再升级）

水位条上画了 **25% / 8% 两条白刻度**，剩多少水才够星，一眼看得见。

### 手感打磨（v3.1 的五件小事）

1. **泥点按水流反方向飞** —— 之前是随机方向，物理上是错的
2. **车漆越洗越亮** —— 清洁度驱动对角高光，每 12.5% 重烘焙一次
3. **水少时水流变细、水声变尖** —— 快没水了，身体先知道
4. **结算金币滚动 + 星星逐个弹出** —— 之前是一次性出现
5. **冲掉顽固油渍时"叮"一声 + 微震** —— 这是唯一一个"某块东西被彻底冲掉"的离散时刻

### 水量预算表（`levels.js` 里的 `water`）

由 `tools/measure.mjs` 实测得出：用自动扫射跑完每关，记录耗水量，
再按"普通玩家约比机器费 1.5 倍水"反推，并用 1 → 0.75 的系数逐关收紧。

| 关 | 水量 | 关 | 水量 |
|---|---|---|---|
| 1 小红轿车 | 430 | 8 白货车 | 220 |
| 2 小黄面包 | 400 | 9 脏轮毂 | 120 |
| 3 涂鸦墙 | 350 | 10 黑武士 | 150 |
| 4 蓝跑车 | 330 | 11 轮毂精洗 | 110 |
| 5 陶罐 | 150 | 12 只洗上半身 | 190 |
| 6 绿越野车 | 285 | 13 只擦玻璃 | 90 |
| 7 老窗户 | 150 | 14 只剩下半身 | 105 |

**这是最需要你亲手调的表**：觉得太紧就整体加 15%，太松就减 15%。只改这一个数字，不用动代码。

> 也可以直接改 `game.js` 顶部的两个总开关，一次影响全部关卡：
> `WATER_BONUS = 1.20`（水量）、`FOAM_BONUS = 1.40`（泡沫量）。现在是偏轻松的档位。

## v4：四个拓展

### 1. 区域化脏污（10 关 → 14 关，零新增美术）

关卡数量从来不等于图片数量。`dirt.regions` 可以把脏污限制在物体的某几个区域：

```js
dirt: {
  density: 1.7,
  recipe: MUD,
  regions: [[0.16, 0.58, 0.26, 0.42], [0.60, 0.58, 0.26, 0.42]]  // 只脏两个轮子
}
```

同一辆小红轿车，现在是「整车」和「轮毂精洗」两关。**脏污生成点会优先落在区域内**，不会出现"区域外脏了却洗不到"。

想加关只要在 `levels.js` 末尾再补一条 `region(...)`。

### 2. 洗前 / 洗后对比

结算卡底部点「洗前洗后」，进一个可拖动分割线的对比视图：左边是开洗前的快照，右边是洗干净的样子。

实现上只是在 `bakeDirt` 时多存了一份 `beforeCv` 快照，渲染时用 clip 切两半。

**这是解压类内容唯一被验证过的传播格式**——人们分享的从来不是"洗的过程"，而是"对比"。

### 3. 泡沫预浸

底部左侧的「泡沫」开关。打着泡沫的地方，冲洗效率 ×2.2。

**它被刻意做成可选的**：

- 泡沫是独立资源（每关 100，每秒耗 26），**不消耗水**
- 不用泡沫，游戏和之前完全一样
- 用得好，能在关键区域省下 20% 左右的水

所以它不破坏已有的水量平衡，只是给愿意钻研的人多一层。泡沫用完会自动切回清水，不会出现"按钮按了没反应"。

### 4. 禅模式

结算卡底部点「禅模式」：无限水、无限泡沫、不记星级、不给金币、不推进关卡。

给"下班只想放空"的人。成本极低（关掉水槽和结算），但可能是**留存最高**的一个模式——因为解压类的核心用户里，很多就是不想被挑战的人。

## v5：工具系统（四种脏，四把工具，一一对应）

之前所有脏东西都是"按住冲就掉"，工具只是快慢不同，所以换了也没用。现在改成**一种脏只认一把工具**：

| 工具 | 只能处理 | 外观 | 消耗 |
|---|---|---|---|
| **冲洗** | 软泥、灰尘、涂鸦 | 浅棕雾状斑点 | 水 |
| **泡沫** | **厚泥**（盖在软泥上面的一层壳） | 深色块状 + 裂纹 | 泡沫 |
| **刮刀** | **硬垢** | 黑亮结块 | 免费 |
| **补漆** | **漆损**（掉漆露底的灰斑） | 灰色斑块（冲掉脏东西才看得见） | 免费 |

三个关键设计：

1. **厚泥是盖在软泥上面的一层**。所以"泡沫 → 冲洗"是两步：先用泡沫化掉壳，再冲掉下面的软泥。泡沫不再是可选项。
2. **用错工具完全没有效果**，并弹一次提示，比如"硬垢要换「刮刀」"。
3. **底部状态栏实时告诉你还差什么**：`还差 厚泥·泡沫 / 2 处硬垢·刮刀 / 2 处掉漆·补漆`。

四样都处理完才算洗完，进度条会停在 85% 等你。

原来的「除油剂」升级项改名为**刮刀头**，效果是"硬垢刮除速度 ×0.55 → ×2.4"。

## v6：一单多车（共用水箱 + 自己选顺序）

有些订单是**两辆车连着洗**，共用一个水箱：

```js
{ id: 'combo_sedan_van', name: '双车套餐', water: 900, fleet: ['sedan', 'van'] }
```

**顺序由你决定**：

- 开局弹出选车卡：缩略图 + 车名 + 脏污种类标签（`软泥` `厚泥` `硬垢×1` `漆损×2`）
- 洗完一辆 → **水箱回补 15%** → 回到选车，挑下一辆
- 压力全在第二辆上：第一辆冲得越干净，第二辆余量越少

HUD 显示 `第 15/16 单 · 2/2 辆`，进度条 = （已完成车辆 + 当前车辆进度）/ 总车辆数。

**为什么这个选择有意义**：每辆车的脏法不一样（小红轿车只有软泥，小黄面包有厚泥 + 硬垢）。软泥吃水、厚泥吃泡沫不吃水。先洗哪辆，决定了你带着多少水去面对下一辆。

现在 16 单：14 个单车 + 2 个双车套餐。

## 关键技术点（踩过的坑）

### 进度算法：从"数格子"改成"称重量"

一开始进度按"有多少格已经干净"算，结果：

- 要冲过 2 遍才跨过阈值 → **第一遍扫过去进度是 0%**，玩家觉得白冲
- 物体边缘那圈只沾一点的像素永远洗不掉 → 卡在 85%，关卡过不去

现在按**冲掉了多少脏东西**（每格 alpha 的减少量）来算，进度每一帧都在动。

### 泥加深几乎没用

试过把污渍从 0.55 加深到 0.80，实测单局耗水只从 83 涨到 89 —— 因为笔刷重叠率高，一遍就冲掉了，加厚只是让边缘脏一点。

**真正决定时长的是笔刷覆盖面积**。把笔刷从 25px 缩到 18px，单局直接从 8 秒变成 16 秒。

### 其他

- 断水后 0.9 秒才结算，让玩家看清"水用完了"
- 移动端地址栏收起/展开会触发 resize，小幅变化只拉伸画布，不重置关卡
- 饱和度高的脏法（涂鸦）用硬边，泥/灰用径向渐变软边

## 已知取舍

- 美术是矢量灰盒，**故意不做精细**。
- 音效是 WebAudio 合成的，只验证"有没有声音"，没验证"好不好听"。
- 只在 Chrome 验证过（含 headless 截图回归），没跑过真机。
- **单关时长受"一个物体"限制**：一辆车就是 20 秒左右。想再长，得做"一单多辆车"或无尽模式，见下。

## 找人测的时候看什么

1. 会不会盯着水位条做取舍？（不会 = 代价不够痛）
2. 水快没了的时候有没有"手紧一下"？（有 = 机制成立）
3. 第一次断水，是想"再来一次"还是"算了"？
4. 会不会主动去升级？（不会 = 数值没打通）

### 迁微信要改的地方

| 模块 | 浏览器版 | 微信小游戏 |
|---|---|---|
| 画布 | `document.getElementById` | `wx.createCanvas()` |
| 尺寸 | `getBoundingClientRect` | `wx.getSystemInfoSync()` + 安全区 |
| 输入 | Pointer Events | `wx.onTouchStart / Move / End` |
| 音效 | WebAudio | `wx.createInnerAudioContext()` |
| 震动 | `navigator.vibrate` | `wx.vibrateShort()` |
| 存档 | `localStorage` | `wx.setStorageSync` |
| 分享 | — | `wx.shareAppMessage` + 录屏 |
